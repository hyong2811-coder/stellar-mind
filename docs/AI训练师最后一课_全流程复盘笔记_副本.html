一、核心职责与角色层级

1.1 最核心的职责

🎯 AI 训练师最核心的职责
不是「给优质数据」，而是承接需求，把需求落地。优质数据只是需求落地的结果——因为算法要用这批数据来微调训练、提升模型能力，才会产生需求。把需求落地做好，已经非常不容易。

1.2 职责细分

📦
数据构建
大厂中少见让你单独构建的情况，中小型公司可能从 0 到 1。特殊情况：原始数据不可获取，需通过模型构造。
📋
规则设计
根据需求撰写标注规则文档，定义数据维度、评分标准、case 案例，确保标注人员理解一致。
🔍
质量管理
搭建抽检体系（抽检比例、动态调整机制）、返修流程、人员准确率追踪。
👥
人员管理
团队组建与培训、分组管理、绩效考核、供应商协同。
📊
评测
构建评测集、设计评测维度、出评测报告。人工 + 自动结合。
🚀
流程/提效
SOP 搭建与优化、自动化脚本、PE 能力、workflow 搭建（如 Coze）。

1.3 角色层级体系

L5
Owner / 经理
全流程 SOP 优化、多项目并行管控、产研思维反推模型迭代、市场分析与数据采集。4年+经验。
L4
POC（项目管理）
100% 需求承接 → 规则落地 → 人员管理 → 交付验收。分甲方 POC 和乙方（供应商）POC。
L3
标注 / 质检
标注：执行标注、保障准确率、理解规则。质检：数据敏感度 + bad case 采集 + 人员培训。
L2
实习生
核心是执行 + 准确率 + 理解规则。部分参与 bad case 采集、辅助分配数据。
💡
甲方 POC vs 供应商 POC甲方 POC 需求承接来自产品/算法，规则自己制定。供应商 POC 80% 的规则由甲方提供（压缩版），核心工作在于内部人员管理和规则优化落地。供应商对接甲方 POC 或产品，极少直接对接算法。

2.2 需求表单核心字段

大公司内部一般都有需求表单系统（如飞书），需在发起时填写以下信息：

字段内容
发起人 / 负责人需求方（算法/产品）+ 数据侧负责人
任务名称与说明模型名称、训练目标、数据类型
数据总量具体条数
标注起止时间开始日期 → Deadline
规则文档初步规则/参考文档
质量要求合格率标准（如 ≥90%）
交付频次与格式每日/每批交付、JSON / CSV 等
预算与人效估算涉及供应商时需算钱（按条 × 准确率）

2.3 需求落地的关键步骤

✅
需求落地 ≠ 需求承接完就结束面试中经常有人只讲「怎么接需求」而漏掉「怎么落地」。落地是面试官最关心的环节。
1
拿到需求后先简单梳理，写出初步规则文档
↓
2
查看数据形态，挑选典型 case 与案例
↓
3
自己先试标一批数据
↓
4
把试标结果给需求方验证，确认是否符合预期
↓
5
如果达标 → 正式落地；如果有偏差 → 双方用同一批数据分别标注，看 gap 在哪，重新制定标准
「我拿到需求后，会先简单梳理成初步规则文档，然后回扫数据形态，挑典型 case 做试标。试标结果提交给需求方确认——如果达标，说明规则落地了；如果有偏差，我会找同一批数据让双方分别标注，找出分歧点，重新制定标准后再落地。」

三、规则文档方法论

3.1 核心注意事项

🔲
全面覆盖，无重叠
维度要广，能覆盖数据各种类型；各维度之间不能有交叉重叠。MECE 原则。
📖
通俗易懂
让标注人员能快速理解，避免过于学术化的表述。
📌
配 Bad Case 案例
每个维度至少有正确/错误示范，case 是规则的灵魂。
🔄
持续更新迭代
规则需要根据作业中发现的新问题及时更新，不是写完就不动了。
✅
可落地性
规则必须可操作，标注员拿到就能干活，不能只有抽象概念。
📐
评分维度明确
每个分值区间的标准清晰，1分/2分/3分的界线不模糊。

3.2 图片/视频项目规则特殊要点

图片和视频项目的规则文档，最核心的内容不是文字描述，而是视觉参考与案例配置：

  • 光影解释（光质、光亮光位、透光）、构图类型（中心构图、三分构图等），每个概念都要配示例图
  • 饱和度区分（低/中/高）需要用对比图片帮助标注员理解
  • 风格分类（水彩、儿童、二次元、实拍等）每个风格配典型示例
  • 对于美学打分项目，需要将主观审美解耦为可量化维度（脸部、身材、服装、发型分别打分）
⚠️
美学项目的特殊难点美学是主观的，怎么落地？① 前期人员筛选时就把审美差的刷掉；② 周期性开会拉齐认知；③ 人工打分与模型打分做一致性对比，gap 大的拉出来讨论，不断拉齐到 90%+ 一致性——这其实就是 RL 的思路。

四、质检流程与返修

4.1 质检方式

方式说明适用场景
互检标注人员之间交叉检查早期人员少、未分出专职质检时
当日检当天标注 → 当天质检项目紧急、质检可能半天标注半天质检
次日检前一天标注 → 次日质检最常见、最合理的节奏
二次抽检返修后对未抽检部分再抽一轮准确率不达标时的补救
💡
抽检比例是动态调整的规则刚更新时，抽检 40% 甚至全检；人员准确率稳定在 95%+ 后，降到 15~20%。面试时要用确定的数据说：「初期 40%，稳定后降到 20%」，不能含糊说「30% 到 40%」。

4.2 返修机制

90%+
合格
只修改抽检中标错的条目即可
70-90%
部分返修
按比例（如 30~50%）打回未抽检部分进行返修，返修后二次抽检
<70%
不合格
全部打回重做，或直接舍弃该批次数据

二次抽检的对象是之前未抽检的部分（包含返修后的数据）。如果二次抽检仍不达标，一般就直接舍弃这个人的数据——三次抽检成本太大了。

4.3 质检人员 vs 标注人员的区别

不只是「准确率更高」，质检人员还需要具备：

  • 数据敏感度：能从数据中发现共性问题
  • Bad case 分析能力：主动采集整理典型错误
  • 人员培训能力：发现标注员的薄弱环节并针对性辅导
  • 沟通协作能力：准确率高但不会沟通的人只适合做标注
✅
质检人员从哪来？① 正式标注 3~7 天后，从标注人员中提拔表现好的；② 大公司可能入职时就按职级定岗；③ 质检人员也可以同时做评测任务（评测是周期性的，中间空档质检人员不能闲着）。

五、评测项目管理

5.1 评测周期分类

周期特点
当天出报告用已有评测集，短平快，当天标完当天出结果
3~10 日最常见。已有评测集，横向维度较多（评测对象多）
10 日以上从零构建评测集 + 评测作业设计 + 标注 + 出报告

现在模型迭代极快，10天内可能就出新版本，所以大多数评测是短平快的 3~6 天。

5.2 评测人员的培养

评测人员需要长期稳定培养，不能每次临时拉人。尤其是美学类的专项评测，需要标准文档 → 试标 → 拉齐地铁值（审美一致性），这是一个「软性培养」过程，周期很长。

「我手下会有稳定的评测专业团队。评测是周期性任务，比如一个月做一回，中间空档他们就做质检。需要评测时，我直接让他们上手评，评完我出报告。不需要每次重新培训。」

六、人员管理

6.1 内部人员管理维度

人员管理从两个核心维度考核：准确率 + 完成率。

完成率指标说明
日完成量 / 日分配量低于 90% 给黄牌
跳过率跳过数 / 分配数 ≥ 10% 给黄牌（防止偷懒跳难题）
质检跳过率累计跳过质检数据 ≥ 20% 给黄牌

6.2 供应商管理

供应商管理的重点在于人员管理。供应商的人比较杂、能力参差不齐。

  • 供应商按计件计酬（按条算钱），标注和质检价格不同
  • 分批分配数据（如每次 60 条），做完报告后再分下一批，不要一次全分
  • 基准线如 200 条/天，低于 100 条/天的人力直接淘汰（太分散，管理成本大于价值）
  • 可找 2~3 家供应商竞标对比质量
  • 奖惩机制用百分比而非固定金额（如准确率 95%+ 奖 10%，低于 90% 扣 10%）

6.3 考核制度（五档）

⭐
优秀
完成任务 + 准确率 95%+。基础薪资 + 奖励
✓
合格
准确率 85%+ 达到合格标准
✗
不合格
准确率 85% 以下，当天数据返修
🟡
黄牌
完成率不达标 / 异常跳过率 / 累计不合格
🔴
红牌
已有黄牌 + 持续表现差 / 态度恶劣 / 不回复消息。无薪

6.4 大型团队管理（百人级）

百人团队最大的问题：信息失真，很难每个人都顾及到。

  • 分组管理：质检人员每人带一批组员，负责定向培训和跟踪准确率
  • 数据量和准确率要求必须非常明确，不能因个别人而松动标准
  • 提拔不上来的人果断舍弃，不要浪费人力资源
  • 预防高频次人员流动：毕业季前提前储备，规定离职需提前 15 天~1 个月通知
  • 遇到缺人先内部调配（从其他组借调），解决不了再找领导

七、交付文档

交付文档（One 配置文档）是项目的最终产出，包含以下内容：

📅 项目背景
周期、时长、需求方、参与人员
📋 规则文档
相关规则文档链接
📊 作业数据
人员每日数据量、准确率
💰 费用结算
涉及供应商时的报账
🐛 Bad Case 分析
作业中发现的典型问题
🔧 优化建议
提效方案、产品迭代建议、复盘总结

八、简历撰写

8.1 核心结构

🚫
简历常见问题① 加粗太多、密密麻麻全是字；② 专业术语堆砌但说不清楚项目干什么；③ 数据夸张离谱（效率提升三倍、下降 60%）；④ 东一榔头西一榔头没有故事感。

简历核心要让 HR 和面试官一眼看出：

  • HR 看关键词：项目管理、人员管理、PE 能力、AI 方向 → 过了就扔进面试池
  • 面试官看项目：是否清晰可表述？中间有没有提效的亮点？能不能展现优势？

8.2 项目描述用 STAR 法则

S 背景
项目背景与需求
→
T 任务
你承接了什么
→
A 行动
规则+落地+卡点+解决
→
R 成果
量化数据结果

每个项目要有侧重点，不是每个项目都写全流程，而是突出核心贡献：

  • 项目 A 侧重人员管理能力
  • 项目 B 侧重评测报告 + 交付能力
  • 项目 C 侧重规则文档撰写能力
  • 项目 D 侧重提效/自动化贡献

8.3 个人优势怎么写

从真实的 JD 中提取关键词，结合自身经历改写：

  • AI 数据标注 + 大模型运营管理 + 内容质量把控经验
  • 人机混合标注工作流经验（= 自动化 + 人工校验）
  • 跨职能协作 + BPO/供应商管理经验
  • 自动化工作流搭建能力（具体到成效）
  • PE（Prompt Engineering）能力 → 写成 Prompt Engineer
  • 评测标准与评测集独立构建能力
  • 多项目并行管理能力
⚠️
专业名词能写但要能讲清楚简历上写的任何专业名词，面试官问「这是什么意思」时，你要能立马解释得特别清楚。说不清楚就别写上去。

8.4 数据要有理有据

简历上的数据（如「效率提升 X%」「准确率提升 X 个点」）一定要是自己能讲出逻辑的。面试官对数字非常敏感，随便写一个讲不清楚就暴露了。

九、面试策略

9.1 面试流程与时长

轮次面试官内容比例
一面平行面（直属 leader）80% 项目 + 20% 个人/AI 前瞻性
二面加一面（leader 的 leader）40~50% 项目 + 50% 自动化/提效/行业认知
三面交叉面综合考察
终面HR / HRBPHR 看方向匹配；HRBP 可能问业务细节

大厂面试一般 40 分钟起步。聊得好可以到 1 小时。

9.2 面试官的三层考察

🔭 宏观层
项目全流程是什么？你的角色是什么？怎么解决问题的？
🔬 微观层
某个环节的细节：bad case 怎么处理？数据案例长什么样？
💎 本质层
你的方法论是什么？能不能迁移到其他项目？如果重新做会怎么做？
🎯 面试官最终要看到的
你不只是执行者，而是有自己的思考和方法论沉淀。你能发现问题、解决问题、持续迭代。自动化就是一个特别好的方法论沉淀的体现。

9.3 实战技巧

表述技巧

  • 总分总：先给结论，再展开，最后总结回扣
  • 停顿思考：面试官问完后，停 1~2 秒，过一下他的问题，想清楚答几个点再答
  • 结论前置：前面和最后一句话印象最深
  • 讲偏了就拉回来：意识到自己赘述了，加一个总结性话术收回来
  • 语速别太快：慢一点，让面试官跟上你的思路

高级技巧

  • 留钩子：「其实这背后的核心问题是 XX，后来我发现了更好的做法，这个经验也用到了其他项目」→ 引导面试官追问你擅长的领域
  • 主动引导：把话题引到自己最擅长的方向（如自动化、PE 能力），尤其在二面更重要
  • 不会的问题：「我之前确实没有实操过，但基于 XX 经验，我认为应该 XX」
  • 听不懂的问题：可以反问确认「您所指的是 XX 方向吗？」不要硬答
「之所以这样设计规则维度，是因为我们发现 XX 问题（留钩子）。其实在这个项目中我还落地了一套自动化方案（引导到擅长领域），通过 Coze workflow 实现了半自动化的数据构造，初期虽然是半人工的，但这是把模型能力引入标注流程的开端。」

9.4 模拟面试实战要点

课上进行了模拟面试，暴露出几个典型问题：

📝 模拟面试问题复盘

问：你怎么构建自己的方法论，怎么把需求更好地落地？

典型错误：只讲了前期需求对齐（背景、时间、数据量），但漏掉了落地环节——怎么试标、怎么验证规则、怎么确认符合需求方预期。

问：0 到 1 梳理标注标准的思路？

如果讲不好结构化的回答，可以用一个实际案例代替：「这个项目就是我当时从 0 到 1 承接的，我当时的做法是……」

问：数据的理想态和标准你做了什么工作？

核心答：规则落地 + 标注过程中问题解决 + 与需求方持续协同校准标准。

🚫
面试大忌① 背书式回答、泛泛而谈；② 夸大角色（说不清细节就暴露了）；③ 不懂装懂；④ 绕来绕去没有核心重点；⑤ 面试官问 SFT 你说只准备了评测项目 → 直接挂。

十、子弹库构建

子弹库是你面试的「弹药库」，分两个层级：

简单版（基础好的人）

把之前已有的项目填充表整理下来，能够自然地讲清每个项目的全流程即可。面试时可以放在屏幕旁边（线上面试），但不要戴眼镜后目光明显偏移。

详细版（讲不清楚的人）

必须做到以下程度：

  1. 每个项目写出详细的规则文档——不是 AI 生成后放着，而是自己一字一字写/过一遍
  2. 准备实际数据样例：原始数据长什么样、标注后长什么样？涵盖不同类别（合格/不合格/舍弃/跳过），每类至少 2~3 条
  3. 评测类项目自己实打实做 20~50 条，涵盖不同分值的 case
  4. 把项目讲给非行业的人听（对象/弟弟妹妹/爸妈），他们听得懂就说明你讲清楚了
💡
子弹库核心内容自我介绍、每个项目的（背景 → 规则维度 → 流程卡点与解决方案 → 结果数据）、团队规模与分工、公司名/模型名/产品名、数据规模与每日分配量。
🧠 AI 是你的外置大脑，不是你的替身
用 AI 辅助梳理没问题，但最终要自己过一遍脑子、手写下来。AI 生产的知识过一遍脑子再写下来，这才是你自己的。面试时磕磕巴巴就说明这个东西还不是你的。

十一、面试复盘方法

每次面试后（不管过没过）都要做复盘，格式参考：

1
基本信息：岗位、简历链接、录音逐字稿
↓
2
面试官核心问题：列出 1234 问了什么
↓
3
回答不足的地方：哪些没答好？核心考察点是什么？
↓
4
改良版回答：把答案优化成「满分答案」
↓
5
下一轮改进策略：需要弥补什么知识点？调研什么材料？
✅
面试就是不断发现问题、解决问题前期广投广撒网，每天投上限，不管大小面试都去面。面完回来复盘、总结问题、优化答案。答不上来的问题太好了——把它变成满分答案，下次再遇到同类问题就不会出错。要么学到（经验），要么拿到（offer）。

每日习惯

  • 每天至少刷一篇 AI 相关文章/视频，记 1~2 个观点，面试时找机会表达出来
  • 面试前搜一下对方公司/产品的最新动态，比如生图模型的评测、竞品对比
  • 同学之间互相模拟面试，从面试官视角发现对方的问题

Reinforcement Learning (from Human Feedback)，强化学习（基于人类反馈）
PE
Prompt Engineering，提示词工程
LoRA
Low-Rank Adaptation，低秩适配微调，小模型微调方案
Caption
图片/视频的描述标注，结构化描述画面内容
One 配置文档
交付文档的内部叫法，包含项目全生命周期信息

面试准备的知识弹药库，包含自我介绍、项目详情、规则文档、case 数据等
